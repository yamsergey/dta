What your agent can't see

Ask why a screen came back broken and it will answer anyway — fluently, citing your files, and with no way for either of you to check it. Not because the model is weak. Because none of this ever reaches it.

  • HTTP status and response body
  • WebSocket frames
  • which class drew the screen
  • recomposition counts
  • WebView DOM, cookies, storage
  • Room rows and SharedPreferences

What it reads, and what it can do

A sidekick library inside your debug build, a daemon on your machine, and an MCP server your agent already knows how to talk to.

Screen analysis

The real view hierarchy — classes, bounds, layout parameters, Compose composable names and recomposition counts, and DOM trees from WebViews and Chrome Custom Tabs. Not the semantic accessibility tree uiautomator dump gives you.

Network analysis

Recording starts when the app does: OkHttp requests, WebSocket connections, Custom Tab and WebView traffic. No "start recording" button, so no missed first request.

Mocking

Mock rules for HTTP and WebSocket, built from traffic it already captured or written from scratch — so an edge case stops being something you wait for.

Build & launch

One call builds the APK with the sidekick injected, installs it and launches it. If the sandbox won't allow it, it prints the commands instead of failing quietly.

Interaction

Tap, swipe, type, press keys — then read the screen and the traffic back to confirm what actually happened. The whole inspect, mock, interact, verify loop without leaving the chat.

App storage

Room and SQLite rows, SharedPreferences, WebView cookies and storage — read directly, so "the cache is stale" is something it checks rather than something it suspects.

Install

Two ways in. The plugin is the shortest path if you live in Android Studio; the CLI is the one to use with Claude Code, Cursor, or anything else that speaks MCP.

Android Studio plugin

Embeds the daemon, injects the sidekick into debug builds, and adds a four-tab inspector — layout, network, WebSocket, MCP.

JetBrains Marketplace

CLI

Java 21 or newer.

brew tap yamsergey/packages
brew install dta-cli
claude mcp add dta -- dta-cli mcp

Then add the sidekick to your debug build

// build.gradle.kts — debug only, never shipped
debugImplementation("io.github.yamsergey:dta-sidekick:0.9.40")

It starts itself through AndroidX Startup — there is nothing to call. The plugin can inject it for you instead, if you would rather not touch the build file.
